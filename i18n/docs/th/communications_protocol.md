# โปรโตคอลการสื่อสารสำหรับการประเมินไอเดีย

เอเจนต์ที่ทำงานในระบบนิเวศการปรับแต่งเมนูบริบทของ Windows ทุกคนต้องปฏิบัติตามโปรโตคอลที่มีโครงสร้างนี้เมื่อโต้แย้ง ประเมิน หรือปรับปรุงไอเดียที่เสนอ

## 1. หลักการ "สตีล-แมน"
ก่อนจะโต้แย้งไอเดีย เอเจนต์ผู้ประเมินต้องสร้างเวอร์ชันที่แข็งแกร่งที่สุดของข้อเสนอเดิมก่อน
- อธิบายคุณค่าหลักให้ชัดเจนกว่าผู้เขียนเดิม
- ระบุประโยชน์ที่ไม่ได้กล่าวถึงของแนวทางอย่างน้อยหนึ่งข้อ

## 2. เรดทีม (การประเมินช่องโหว่)
เมื่อไอเดียแข็งแกร่งแล้ว เอเจนต์ต้องท้าทายตามเวกเตอร์ต่อไปนี้:
- **ความเหมาะกับระบบนิเวศ:** รู้สึกเหมือนเครื่องมือเมนูบริบทดั้งเดิม หรือพยายามเป็นแอปพลิเคชันเต็มรูปแบบ?
- **ประสิทธิภาพ:** จะเกิดอะไรขึ้นหากรันโดยบังเอิญในไดเรกทอรีที่มีไฟล์ 100,000 ไฟล์?
- **ความเสียหาย:** มีความเสี่ยงต่อการสูญเสียข้อมูลที่ไม่สามารถกู้คืนได้หรือไม่?
- **ภาระพึ่งพา:** ต้องพึ่งพาภายนอกมากเกินไปหรือไม่ (เช่น ไลบรารี Python ขนาดใหญ่หรือไบนารีที่ไม่ได้ติดตั้ง)?

## 3. รูปแบบการโต้แย้ง
การวิจารณ์ใดๆ ต้องมีโครงสร้างดังนี้:
- **สมมติฐาน:** ไอเดียต้องการแก้ปัญหาอะไร
- **ช่องโหว่:** ข้อบกพร่องหรือความเสี่ยงเฉพาะที่ระบุ
- **การกำหนดทางเลือก:** การพลิกที่เสนอซึ่งคงคุณค่าไว้พร้อมกับลดความเสี่ยง

## 4. กลไกคำตัดสินสุดท้าย
ห้ามปฏิเสธไอเดียโดยตรงโดยไม่เสนอการพลิก เว้นแต่จะก่อความเสี่ยงร้ายแรงต่อระบบไฟล์ (เช่น การลบแบบวนซ้ำที่ไม่มีการติดตาม)
