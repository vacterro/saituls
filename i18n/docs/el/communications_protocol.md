# Πρωτόκολλο επικοινωνίας για την αξιολόγηση ιδεών

Όλοι οι μεταγενέστεροι πράκτορες που εργάζονται στο οικοσύστημα προσαρμογής του μενού περιβάλλοντος των Windows πρέπει να τηρούν αυτό το δομημένο πρωτόκολλο όταν αμφισβητούν, αξιολογούν ή βελτιώνουν προτεινόμενες ιδέες.

## 1. Το δόγμα του "Steel-Man"
Πριν αμφισβητήσει μια ιδέα, ο αξιολογητής πρέπει να κατασκευάσει την ισχυρότερη δυνατή εκδοχή της αρχικής πρότασης.
- Να διατυπώσει την κεντρική πρόταση αξίας πιο καθαρά από τον αρχικό συγγραφέα.
- Να εντοπίσει τουλάχιστον ένα αδήλωτο όφελος της προσέγγισης.

## 2. Red-Teaming (αξιολόγηση τρωτότητας)
Μόλις ενισχυθεί η ιδέα, οι πράκτορες πρέπει να την αμφισβητήσουν κατά μήκος των ακόλουθων διανυσμάτων:
- **Ταίριασμα οικοσυστήματος:** Αυτό μοιάζει με εγγενές εργαλείο μενού περιβάλλοντος ή προσπαθεί να είναι πλήρης εφαρμογή;
- **Απόδοση:** Τι συμβαίνει αν εκτελεστεί κατά λάθος σε κατάλογο με 100.000 αρχεία;
- **Καταστροφικότητα:** Υπάρχει κίνδυνος μη αναστρέψιμης απώλειας δεδομένων;
- **Κόστος εξαρτήσεων:** Απαιτεί υπερβολικές εξωτερικές εξαρτήσεις (π.χ. τεράστιες βιβλιοθήκες Python ή μη εγκατεστημένα δυαδικά αρχεία);

## 3. Η μορφή της αντίκρουσης
Οποιαδήποτε κριτική πρέπει να δομηθεί ως εξής:
- **Υπόθεση:** Τι στοχεύει να λύσει η ιδέα.
- **Τρωτότητα:** Το συγκεκριμένο ελάττωμα ή ο κίνδυνος που εντοπίστηκε.
- **Εναλλακτική διατύπωση:** Μια προτεινόμενη στροφή που διατηρεί την αξία ενώ μετριάζει τον κίνδυνο.

## 4. Μηχανισμός τελικής ετυμηγορίας
Οι ιδέες δεν πρέπει να απορρίπτονται εντελώς χωρίς πρόταση στροφής, εκτός αν αποτελούν καταστροφικό κίνδυνο για το σύστημα αρχείων (π.χ. μη παρακολουθούμενη αναδρομική διαγραφή).
